Flyweight

O objetivo do padrão Flyweight é reduzir o consumo de memória através do compartilhamento de objetos.

Em vez de criar milhares de objetos iguais, reutilizamos instâncias já existentes.

Palavras-chave da prova:
  • muitos objetos
  • objetos repetidos
  • economia de memória
  • compartilhamento

Problema Sem Flyweight

Imagine um jogo com 100.000 árvores. 


for(int i = 0; i < 100000; i++) {
    Arvore arvore = new Arvore(
        "Carvalho",
        "Verde",
        texturaGigante
    );
}

Estamos criando milhares de objetos praticamente idênticos.

Problema Visual

🌳 🌳 🌳 🌳 🌳 🌳 🌳 🌳 🌳 🌳

muita memória desperdiçada

Solução com Flyweight


class ArvoreFlyweight {

    private String tipo;
    private String cor;
    private Textura textura;

}

Criamos apenas UMA instância compartilhada entre milhares de árvores.

Flyweight Factory


public class ArvoreFactory {

    private static Map
        cache = new HashMap<>();

    public static ArvoreFlyweight get(
        String tipo
    ) {
        return cache.computeIfAbsent(
            tipo,
            t -> new ArvoreFlyweight()
        );
    }
}

A fábrica evita criar objetos repetidos.

Antes x Depois

Sem Flyweight Com Flyweight
100.000 objetos 1 objeto compartilhado
Muita memória Pouca memória
Duplicação Reuso

Exemplos Reais

  • Caracteres em editores de texto
  • Árvores em jogos
  • Ícones repetidos em interfaces
  • Emojis em aplicativos
  • Sprites em engines de jogos

Como Identificar na Prova?

Se o enunciado falar:

  • grande quantidade de objetos
  • objetos idênticos
  • consumo excessivo de memória
  • compartilhamento de instâncias
Resposta quase sempre: Flyweight

Questão Clássica de Prova

Um sistema cria milhares de objetos iguais e está consumindo memória excessivamente.

Qual padrão pode ser utilizado?

  • A) Decorator
  • B) Composite
  • C) Singleton
  • D) Flyweight
  • E) Bridge
Resposta: D) Flyweight
