Aulas 02 e 03 · Revisão do ciclo de uma aplicação web

Abertura · Recapitulando

Uma aplicação web é uma conversa.

O usuário faz uma ação. O navegador envia uma requisição. O servidor processa. Os dados são consultados ou gravados. Uma resposta volta.

USUÁRIOinterage
→
NAVEGADORmonta a requisição
→
SERVIDORprocessa
→
RESPOSTAvolta à tela
O mapa da aula

Cada tecnologia tem uma responsabilidade.

HTML estrutura e significado do conteúdo
CSS aparência, layout e adaptação de tela
JavaScript eventos e comportamento no navegador
PHP regras, validação e processamento no servidor
BANCO DE DADOS persistência e consulta das informações
Não são cinco maneiras de fazer a mesma coisa. São peças diferentes trabalhando juntas.
Parte 01 · Frontend

HTML: a estrutura.

HTML descreve

  • Campos e formulários
  • Títulos e textos
  • Botões e links
  • Seções e navegação
<form id="cadastro">
  <label for="nome">Nome</label>
  <input id="nome" name="nome">

  <button type="submit">
    Cadastrar
  </button>
</form>
HTML não valida regras de negócio nem salva os dados. Ele estrutura a interface e os controles.
Parte 01 · Frontend

CSS: apresentação e organização visual.

CSS controla

  • Cores e tipografia
  • Espaçamento
  • Flexbox e Grid
  • Responsividade
  • Estados visuais
.formulario {
  display: grid;
  gap: 16px;
  max-width: 560px;
}

button {
  padding: 14px 20px;
  cursor: pointer;
}

CSS muda como a interface aparece. Não muda a regra de negócio.

Parte 01 · Frontend

JavaScript: comportamento no navegador.

EVENTOclique / submit / input
→
JAVASCRIPTexecuta uma função
→
DOMatualiza a interface
const formulario = document.querySelector('#cadastro');

formulario.addEventListener('submit', (evento) => {
  evento.preventDefault();

  const nome = document.querySelector('#nome').value;
  document.querySelector('#resultado').textContent =
    `Olá, ${nome}!`;
});
O DOM é a representação da página que o JavaScript consegue consultar e modificar.
Conectando as peças

O navegador não é o servidor.

No navegador

HTML + CSS + JavaScript

Interface, interação, feedback imediato e preparação dos dados.

No servidor

PHP

Recebe requisições, valida dados, aplica regras e conversa com o banco.

O JavaScript pode ajudar na experiência, mas a validação importante precisa acontecer também no servidor.
Parte 02 · HTTP

Como o navegador envia os dados?

FORMULÁRIOdados preenchidos
→
HTTP REQUESTmétodo + endereço + dados
→
PHPrecebe e processa

GET

Dados geralmente aparecem na URL.

Útil para consultas, filtros e buscas.

$_GET

POST

Dados são enviados no corpo da requisição.

Comum em cadastros e alterações.

$_POST
HTTP · Formulário

O atributo name identifica o dado enviado.

<form action="processar.php" method="POST">
  <label for="email">E-mail</label>
  <input type="email" id="email" name="email">

  <button type="submit">Enviar</button>
</form>
O id identifica o elemento na página. O name define a chave enviada ao servidor.
Parte 03 · PHP

PHP recebe os dados da requisição.

<?php

$nome = $_POST['nome'] ?? '';
$email = $_POST['email'] ?? '';

echo 'Nome: ' . htmlspecialchars($nome);
echo 'E-mail: ' . htmlspecialchars($email);

O PHP não acessa o campo visualmente. Ele recebe os dados enviados na requisição HTTP.

PHP · Validação

Dados recebidos não são dados confiáveis.

Validar

O dado atende à regra?

  • Está preenchido?
  • Tem formato válido?
  • Está dentro do limite?

Escapar

Como exibir o dado com segurança?

  • HTML: htmlspecialchars()
  • SQL: consultas preparadas
$email = trim($_POST['email'] ?? '');

if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    echo 'E-mail inválido';
}
O ciclo completo · Até aqui

Da interação à regra de negócio.

1. HTML formulário com campos
2. CSS interface legível e responsiva
3. JavaScript evento submit, feedback e interação
4. HTTP envia os dados para o servidor
5. PHP recebe, valida e processa

Mas, se o PHP terminar de executar, onde os dados ficam?

Aula 03 · Persistência
SQL

Os dados precisam continuar existindo.

PHP + banco de dados

Banco de dados

Variável não é persistência.

Memória durante a execução

$nome = 'Ana';

Quando a requisição termina, essa variável deixa de existir.

Banco de dados

Armazena informações para serem recuperadas em outras requisições, sessões e dias.

Persistência

Cada requisição PHP normalmente começa uma nova execução. O banco mantém os dados entre elas.
Banco de dados relacional

Uma tabela organiza registros.

idnomeemailcurso
1Ana Limaana@email.comHTML
2João Souzajoao@email.comPHP
3Ravi Alvesravi@email.comCSS

Coluna

Define um atributo, como nome ou e-mail.

Linha

Representa um registro armazenado.

SQL · Consultar

SELECT busca informações.

SELECT id, nome, email
FROM alunos
WHERE curso = 'PHP'
ORDER BY nome;
SELECTquais colunas?
→
FROMqual tabela?
→
WHEREqual condição?

SQL é a linguagem usada para consultar e manipular dados em bancos relacionais.

SQL · Alterar dados

As quatro operações fundamentais.

CREATE / INSERT

Criar registro

INSERT INTO alunos
(nome, email)
VALUES ('Ana', 'ana@email.com');

READ / SELECT

Consultar registros

SELECT *
FROM alunos;

UPDATE

Atualizar registro

UPDATE alunos
SET curso = 'PHP'
WHERE id = 1;

DELETE

Excluir registro

DELETE FROM alunos
WHERE id = 1;
CRUD: Create, Read, Update e Delete. A base de quase todo sistema de cadastro.
PHP + banco de dados

O PHP conversa com o banco usando PDO.

NAVEGADORenvia formulário
→
PHPvalida e prepara SQL
↔
MYSQLconsulta ou grava
PDO é uma interface do PHP para acessar bancos de dados. A aplicação não deve montar SQL concatenando dados do usuário.
PDO · Conexão

Conectar ao banco.

$pdo = new PDO(
    'mysql:host=localhost;dbname=escola;charset=utf8mb4',
    'usuario',
    'senha',
    [
        PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION
    ]
);

Uma conexão permite que o PHP envie comandos SQL ao banco e receba resultados.

PDO · Inserção segura

INSERT com parâmetros.

$sql = 'INSERT INTO alunos (nome, email)
        VALUES (:nome, :email)';

$stmt = $pdo->prepare($sql);

$stmt->execute([
    'nome' => $nome,
    'email' => $email
]);
Consultas preparadas separam o comando SQL dos valores enviados pelo usuário. Isso ajuda a prevenir SQL Injection.
PDO · Consulta

SELECT e recuperação dos resultados.

$stmt = $pdo->query(
    'SELECT id, nome, email FROM alunos'
);

$alunos = $stmt->fetchAll(PDO::FETCH_ASSOC);

foreach ($alunos as $aluno) {
    echo htmlspecialchars($aluno['nome']);
}

O PHP recebe os registros e pode transformá-los em HTML para o navegador.

Arquitetura do ciclo

USUÁRIO preenche e envia o formulário
HTML + CSS + JAVASCRIPT interface, estilo e eventos DOM
HTTP requisição POST
PHP recebe, valida e aplica regras
PDO + SQL consulta ou altera os dados
BANCO DE DADOS armazena de forma persistente
PHP → HTTP → NAVEGADOR resposta e atualização da tela
