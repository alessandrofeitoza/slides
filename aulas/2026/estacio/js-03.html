01 — Onde estão os dados?

Usuário→Interface→API→Banco de dados
Dados locais
const usuarios = [
  { nome: 'Ana', email: 'ana@example.com' },
  { nome: 'João', email: 'joao@example.com' }
];
Dados externos
// Os dados chegam de outro sistema
const resposta = await fetch('/api/usuarios');
const usuarios = await resposta.json();
  • Até agora, os dados dos exemplos estavam escritos no próprio JavaScript.
  • Na prática, os dados podem vir de um servidor ou serviço externo.
  • Uma API define como outro programa pode solicitar e enviar dados.

02 — O que acontece numa requisição?

Requisição HTTP→Servidor→Resposta HTTP
A requisição pode conter
  • Endereço (URL) do recurso.
  • Método, como GET ou POST.
  • Cabeçalhos e, em alguns casos, corpo da requisição.
A resposta contém
  • Status HTTP, como 200 ou 404.
  • Cabeçalhos que descrevem a resposta.
  • Um corpo que pode conter JSON, texto ou outros dados.
A API não é o banco de dados: é a interface de comunicação entre sistemas.

03 — JSON: um formato para trocar dados

Exemplo de JSON
{
  "id": 7,
  "name": "Ana Silva",
  "email": "ana@example.com",
  "address": {
    "city": "Fortaleza"
  }
}
Acessando os dados em JS
usuario.name
// "Ana Silva"

usuario.address.city
// "Fortaleza"

usuarios.map(usuario => usuario.name);
  • JSON significa JavaScript Object Notation.
  • É um formato textual muito usado para enviar dados pela web.
  • JSON se parece com objetos JavaScript, mas é texto até ser convertido.

04 — A primeira requisição com fetch()

JavaScript
fetch('https://jsonplaceholder.typicode.com/users')
  .then(resposta => resposta.json())
  .then(usuarios => {
    console.log(usuarios);
  });
O que está acontecendo?
  • fetch() inicia uma requisição HTTP.
  • A resposta chega depois, não imediatamente.
  • resposta.json() lê e converte o corpo para dados JavaScript.
  • O resultado é uma Promise.
A chamada não “congela” a página enquanto espera a rede responder.

05 — Por que o código é assíncrono?

Inicia pedido→JavaScript continua→Resposta chega→Continua o trabalho
Não funciona assim
const resposta = fetch('/api/usuarios');

console.log(resposta);
// Promise, não a lista de usuários
Uma Promise representa
  • Uma operação cujo resultado estará disponível no futuro.
  • Um resultado concluído ou uma falha.
  • Uma forma de encadear o que deve acontecer depois.
  • Rede, arquivos e temporizadores podem levar tempo.
  • O navegador precisa continuar respondendo às interações durante a espera.

06 — async e await deixam o fluxo mais legível

Com async / await
async function carregarUsuarios() {
  const resposta = await fetch(
    'https://jsonplaceholder.typicode.com/users'
  );

  const usuarios = await resposta.json();
  console.log(usuarios);
}

carregarUsuarios();
Ideias principais
  • async declara uma função assíncrona.
  • await espera uma Promise dentro de uma função assíncrona.
  • O código fica com aparência sequencial, mas não bloqueia toda a página.
  • Use try/catch para tratar falhas.

07 — Resposta HTTP não é sinônimo de sucesso

Verifique o status
const resposta = await fetch(url);

if (!resposta.ok) {
  throw new Error(
    `Erro HTTP: ${resposta.status}`
  );
}

const dados = await resposta.json();
Por que isso importa?
  • fetch() normalmente não rejeita a Promise só porque recebeu 404 ou 500.
  • resposta.ok indica status HTTP de sucesso (200–299).
  • Erros de rede e erros HTTP são situações diferentes.
Não trate toda resposta recebida como se fosse uma lista válida de dados.

08 — Estados da interface

Uma interface que depende da rede precisa explicar o que está acontecendo.

CARREGANDO

A requisição ainda está em andamento.

SUCESSO

Os dados chegaram e podem ser exibidos.

VAZIO

A requisição deu certo, mas não há resultados.

ERRO

Não foi possível obter ou processar os dados.

Esses estados evitam uma tela aparentemente travada ou sem explicação.

09 — Do JSON para o DOM

Dados → elementos
usuarios.forEach(usuario => {
  const item = document.createElement('li');
  item.textContent =
    `${usuario.name} — ${usuario.email}`;
  lista.append(item);
});
A mesma ideia da aula anterior
  • Ana Silva — ana@example.com
  • João Lima — joao@example.com
  • Ravi Costa — ravi@example.com

Array de objetos → lista de elementos HTML

  • O DOM continua sendo a forma de apresentar os dados na página.
  • A diferença é a origem dos dados: agora eles vêm de uma requisição.
  • Limpe a lista antes de renderizar novamente para evitar duplicação.

10 — Vamos carregar usuários de verdade

Exemplo completo
async function carregarUsuarios() {
  status.textContent = 'Carregando...';
  lista.replaceChildren();

  try {
    const resposta = await fetch(url);
    if (!resposta.ok) throw new Error('HTTP');

    const usuarios = await resposta.json();
    usuarios.forEach(usuario => {
      const item = document.createElement('li');
      item.textContent = `${usuario.name} — ${usuario.email}`;
      lista.append(item);
    });

    status.textContent = `${usuarios.length} usuários carregados`;
  } catch (erro) {
    status.textContent = 'Erro ao carregar usuários';
  }
}
Experimente no slide

Clique para iniciar a requisição.

  • O exemplo usa a API pública de demonstração JSONPlaceholder.
  • É necessário estar conectado à internet para executar a demonstração.

11 — Erro também faz parte do fluxo

Tratamento de falhas
try {
  const resposta = await fetch(url);

  if (!resposta.ok) {
    throw new Error('Falha na resposta');
  }

  const dados = await resposta.json();
} catch (erro) {
  console.error(erro);
  status.textContent =
    'Não foi possível carregar os dados.';
}
Boas perguntas
  • O que a pessoa vê enquanto espera?
  • O que acontece se a conexão cair?
  • Como ela sabe que pode tentar de novo?
  • O erro técnico deve ser mostrado diretamente ao usuário?

12 — Exercício guiado

Construir uma lista de usuários
  • Buscar os usuários na API https://jsonplaceholder.typicode.com/users.
  • Mostrar nome, e-mail e cidade.
  • Exibir uma mensagem enquanto os dados carregam.
  • Exibir uma mensagem clara se ocorrer um erro.
  • Adicionar um campo para filtrar usuários pelo nome.
  • Mostrar uma mensagem quando a busca não encontrar ninguém.
Conceitos usados

fetch · HTTP · JSON · Promise · async/await · try/catch · DOM · eventos · arrays

Para discutir

O que muda quando os dados vêm da rede?

  • A resposta pode demorar ou falhar.
  • Os dados podem mudar sem alterar o código da página.
  • A interface precisa representar carregamento, sucesso, vazio e erro.
  • Como evitar que a interface mostre dados antigos ou duplicados?
Boas práticas

Pequenas escolhas que evitam problemas

  • Verifique resposta.ok antes de tratar o corpo como sucesso.
  • Use try/catch para falhas que possam acontecer.
  • Mostre feedback durante o carregamento e quando não houver resultados.
  • Prefira textContent ao inserir dados externos como texto.
  • Separe a busca dos dados da função que renderiza a interface.
