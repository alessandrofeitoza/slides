Como organizar o código para que cada parte tenha uma responsabilidade clara?

02 · Conceito

MVC: Model · View · Controller

Um padrão arquitetural que organiza a aplicação em responsabilidades distintas.

02 · Conceito

As três responsabilidades

VIEW

Apresentação

Exibe informações e oferece interação ao usuário.

Ex.: formulário e listagem de alunos.

CONTROLLER

Controle

Recebe a requisição, coordena a operação e escolhe a resposta.

Ex.: cadastrar, listar, editar.

MODEL

Modelo

Representa conceitos do domínio, dados e regras relacionadas.

Ex.: Aluno e operações do domínio.

A camada de dados pode ser separada em repositórios ou classes de persistência. MVC não exige uma única estrutura de pastas.

03 · Fluxo de uma requisição

O que acontece ao cadastrar um aluno?

Fluxo didático simplificado. A implementação pode incluir roteamento, serviços, repositórios e tratamento de erros.

03 · Fluxo de uma requisição

O Controller não deve fazer tudo

Responsabilidade do Controller

  • Receber os dados.
  • Acionar validações.
  • Solicitar operação ao Model.
  • Decidir a resposta.

Evite transformá-lo em...

  • Uma página HTML inteira.
  • Um conjunto de consultas SQL.
  • Um lugar para todas as regras.
  • Um arquivo impossível de testar.

Controller coordena. Model trata o domínio. View apresenta.

Mas antes: um pouco de organização do PHP

Preparação · PHP

Antes de falar sobre classes, vamos falar sobre funções

Uma função permite agrupar instruções que executam uma tarefa específica.


function cadastrarAluno(string $nome): void
{
    echo "Aluno cadastrado: " . $nome;
}

cadastrarAluno("Maria");

Por que utilizar funções?

  • Evitar repetição de código.
  • Organizar instruções por responsabilidade.
  • Facilitar a leitura e a manutenção.

Preparação · PHP

Uma classe é uma estrutura para organizar código

Em PHP, podemos agrupar funções relacionadas dentro de uma estrutura chamada classe.


class Aluno
{
    public function cadastrar(): void
    {
        echo "Cadastrando aluno...";
    }

    public function listar(): void
    {
        echo "Listando alunos...";
    }

    public function excluir(): void
    {
        echo "Excluindo aluno...";
    }
}

Observe: as operações relacionadas a alunos estão agrupadas em uma mesma estrutura.

Preparação · PHP

Métodos são funções declaradas dentro de uma classe

Função


function somar(
    int $a,
    int $b
): int {
    return $a + $b;
}

Método


class Calculadora
{
    public function somar(
        int $a,
        int $b
    ): int {
        return $a + $b;
    }
}

A lógica é semelhante. A diferença que estamos estudando agora é onde a função foi declarada.

View: o formulário

<form action="/alunos" method="POST">
    <label for="nome">Nome</label>
    <input id="nome" name="nome" required>

    <label for="email">E-mail</label>
    <input id="email" name="email" type="email" required>

    <button type="submit">Salvar</button>
</form>

A View cuida da apresentação. Não deve abrir conexão com o banco nem executar SQL.

05 · Código

Controller: recebe e coordena

<?php

class AlunoController
{
    public function store(): void
    {
        $nome = trim($_POST['nome'] ?? '');
        $email = trim($_POST['email'] ?? '');

        if ($nome === '' || !filter_var($email, FILTER_VALIDATE_EMAIL)) {
            http_response_code(422);
            require __DIR__ . '/../Views/alunos/criar.php';
            return;
        }

        $aluno = new Aluno();
        $aluno->criar($nome, $email);

        header('Location: /alunos');
        exit;
    }
}

Exemplo simplificado. Em um projeto real, dependências, validações e erros merecem estrutura própria.

05 · Código

Model: representa e opera sobre o domínio

<?php

class Aluno
{
    public function criar(string $nome, string $email): void
    {
        $pdo = require __DIR__ . '/../../config/database.php';

        $sql = 'INSERT INTO alunos (nome, email)
                VALUES (:nome, :email)';

        $stmt = $pdo->prepare($sql);
        $stmt->execute([
            'nome' => $nome,
            'email' => $email,
        ]);
    }
}

Em aplicações maiores, é comum separar persistência em Repository e configurar dependências fora do Model.

06 · Atenção aos conceitos

MVC não é simplesmente criar três pastas

Não significa

  • Colocar todo SQL em qualquer arquivo chamado Model.
  • Colocar toda regra dentro do Controller.
  • Criar pastas sem entender o motivo.

Significa

  • Definir responsabilidades.
  • Reduzir acoplamento desnecessário.
  • Organizar o fluxo.
  • Facilitar evolução e testes.

Separar responsabilidades não é burocracia: é reduzir o custo de mudar o sistema.

07 · Prática guiada

Desafio: cadastro de alunos com MVC

Missão

Implementar o cadastro de um aluno seguindo a separação MVC.

  • View: formulário com nome e e-mail.
  • Controller: recebe e valida os dados.
  • Model: realiza o cadastro.
  • Banco: armazena o registro.

Critérios de sucesso

O cadastro funciona.

Os dados são validados.

O SQL não está na View.

O HTML não está no Model.

O Controller coordena o fluxo.
