Discussão 01

HTTP 200 não é certificado de qualidade

O endpoint respondeu?

É uma evidência de que uma requisição foi processada.

O sistema se comportou corretamente?

É preciso verificar regras, permissões, consistência e falhas.

Uma API pode responder rápido, com status 200, e ainda produzir um resultado errado.

Peça um exemplo de resposta HTTP 200 que represente um erro de negócio. Ex.: pedido confirmado sem reservar estoque.

Pergunta 04 · Múltipla escolha

API gerada por IA: e agora?

O que fazer primeiro quando a IA gera uma API que funciona no cenário ideal?
Happy path

Dados válidos, usuário autorizado e dependências disponíveis.

Casos de falha

Dados inválidos, recurso inexistente e falha de persistência.

Não basta perguntar “funciona?”. Precisamos descobrir em quais condições deixa de funcionar.

Depois da votação, pergunte que teste fariam primeiro e por quê. Não revele a alternativa correta antes da participação.

Pergunta 06 · Múltipla escolha

Autenticado não significa autorizado

Um usuário altera o ID do pedido na URL e consegue acessar o pedido de outra pessoa. Qual é o problema?
GET /api/pedidos/123 Authorization: Bearer <token>
Autenticação

Quem está fazendo a requisição?

Autorização

Essa pessoa pode acessar este recurso?

IDOR: a API precisa verificar a permissão sobre o recurso, não apenas a validade do token.

Pergunte por que esconder o botão na interface não resolve. Reforce que a autorização deve ser verificada no servidor em cada operação relevante.
Pergunta 07 · Múltipla escolha

Pedido salvo. Estoque não reservado.

O pedido foi salvo, mas a reserva do estoque falhou. O que deveria acontecer?
Criar pedido
OK
→
Registrar itens
OK
→
Reservar estoque
Falhou

A operação precisa preservar a consistência do negócio.

Quando as etapas pertencem à mesma transação local, o rollback desfaz as alterações parciais.

Discuta o limite da transação: operações externas, como pagamento em outro serviço, exigem outras estratégias, como compensação ou saga. Não prometa que um rollback SQL desfaz qualquer efeito externo.

Pergunta 09 · Múltipla escolha

O cliente pediu uma funcionalidade

Um cliente solicita uma funcionalidade. Qual deve ser sua primeira preocupação?
Exemplo: “Preciso de um botão para exportar meus relatórios.”

Quem precisa do relatório? Que decisão será tomada com ele? Qual dificuldade existe hoje? O botão resolve o problema?

Pedido de funcionalidade não é definição de problema.

Reforce que entender o problema não significa ignorar o pedido do cliente. Significa investigar se a solução solicitada é a melhor resposta para a necessidade.

Pergunta 11 · Múltipla escolha

Entrega incremental

Em um projeto com prazo de duas semanas, qual abordagem você considera melhor?
Abordagem A

Duas semanas construindo tudo. Uma entrega no último dia.

Abordagem B

Pequenas entregas funcionais, validação e evolução contínua.

Entregar em partes não significa entregar pedaços incompletos. Significa entregar pequenos fluxos que já resolvem alguma coisa.

Conecte com Elephant Carpaccio já apresentado. Peça que identifiquem uma entrega pequena que possa ser demonstrada e validada.
Pergunta 12 · Múltipla escolha

O que gera mais valor?

Qual entrega cria mais valor para alguém que precisa vender um produto?
Selecionar produto
→
Informar dados
→
Confirmar pedido

O usuário não compra arquitetura. Ele precisa realizar uma atividade.

Banco, CRUD, autenticação e documentação são importantes, mas precisam servir ao fluxo de valor.

Evite desvalorizar arquitetura. A ideia é discutir sequência e valor observável, não dizer que infraestrutura ou qualidade técnica são dispensáveis.
